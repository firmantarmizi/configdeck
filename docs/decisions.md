# Design Decisions

Keputusan berikut mengisi detail yang tidak ditentukan penuh oleh SPEC. Perubahan keputusan harus memperbarui dokumen desain dan migration sebelum implementasi terkait.

| ID | Keputusan | Alasan / konsekuensi |
|---|---|---|
| D-001 | `change_requests` adalah header change set; item individual berada di `change_request_items`. | Spec meminta satu request berisi banyak perubahan, sementara contoh schema tampak satu row per variable. Pemisahan ini menjaga apply/audit atomik. |
| D-002 | Status berada pada change set. Approval dicatat terpisah. `READY_TO_APPLY` berarti approved dan semua ADD/UPDATE fulfilled. | Menghilangkan status `APPROVED` yang tidak ada dalam enum spec tanpa kehilangan jejak reviewer. Bila fulfilled lebih dulu status kembali `REQUESTED`; bila approval lebih dulu tetap `NEEDS_INPUT` sampai lengkap. |
| D-003 | Current variable hanya dimutasi saat `Mark Applied`; direct Operator edit membuat change set internal yang mengikuti preview/apply, bukan diam-diam menyatakan deployed. | Menjaga perbedaan Saved in ConfigDeck vs Applied to deployment platform. UI boleh membuat workflow ini terasa langsung, tetapi state transition tetap eksplisit. |
| D-004 | Optimistic concurrency memakai `base_variable_version` per item dan preview fingerprint. | Mencegah stale preview atau dua request menimpa current state. Konflik harus direview/rebase, bukan last-write-wins. |
| D-005 | Variable memakai soft delete/tombstone dan history immutable; key dapat direvive dengan version berikutnya. | History dan foreign key tetap utuh, sementara export hanya memilih row aktif. Ciphertext history tetap tersedia sesuai authorization. |
| D-006 | ID UUID disimpan sebagai lowercase canonical `TEXT`; timestamp sebagai RFC 3339 UTC `TEXT`. | SQLite tidak mempunyai native UUID/TIMESTAMPTZ. Format ini portable dan lexically sortable bila canonical. |
| D-007 | Organization tunggal direpresentasikan row `organizations`, dan entity utama menyimpan `organization_id`. | Mendukung setting TOTP dan boundary masa depan tanpa membuat SaaS multi-tenant. Tidak ada UI multi-organization pada MVP. |
| D-008 | Role adalah enum tetap `CONTRIBUTOR`, `OPERATOR`, `ADMINISTRATOR`; "manage role" berarti assignment, bukan custom role builder. | Spec menetapkan minimal tiga capability-based roles tetapi custom RBAC akan menambah scope/kompleksitas. |
| D-009 | Operator/Admin memiliki global environment visibility; Contributor memerlukan service grant `READ_REQUEST`. | Sesuai capability spec. Schema access menyisakan `access_level` untuk future expansion tanpa environment permission di MVP. |
| D-010 | Contributor tidak memperoleh bulk `.env` export pada MVP, walau seluruh value kebetulan public. | Memperkecil jalur exfiltration dan mengikuti fitur export yang didefinisikan untuk Operator. Individual public copy tetap boleh. |
| D-011 | KEK file menggunakan base64 standard yang decode menjadi tepat 32 byte. | Format tunggal menghindari deteksi hex/base64 ambigu dan mudah dipasang sebagai Docker secret. |
| D-012 | TOTP seed dienkripsi dengan purpose-derived key dari KEK; environment values memakai per-environment DEK. | Melindungi TOTP at rest sekaligus menjaga domain separation. KEK rotation juga harus me-encrypt ulang TOTP seed, bukan sekadar DEK rewrap. |
| D-013 | Session idle 30 menit, absolute 12 jam, recent-auth 5 menit sebagai default awal. | Berada dalam rentang spec dan dapat dikonfigurasi dengan guardrail setelah operational feedback. |
| D-014 | TOTP tidak memiliki recovery code pada MVP; reset oleh Administrator diaudit dan mencabut session. | Menghindari penyimpanan recovery secret tambahan; perlu minimal satu Administrator operasional cadangan. |
| D-015 | Semua authenticated pages private; setiap response yang berisi restricted plaintext memakai `no-store` + `Pragma: no-cache`. | Defense terhadap browser/proxy cache leakage. Secret tidak pernah diletakkan di URL. |
| D-016 | Import `.env` tidak melakukan interpolation, shell expansion, command substitution, atau silent duplicate overwrite. Duplicate/invalid input harus diselesaikan di preview. | Parser adalah data-only dan aman; default visibility semua imported value adalah restricted. |
| D-017 | Audit table dilindungi append-only trigger; off-host/tamper-evident audit chaining ditunda. | Memberi defense terhadap bug aplikasi, tetapi host/DB owner tetap trust boundary. |
| D-018 | Backup filename dibuat server dalam UTC dan hanya basename strict di `/backup`; restore tetap offline dengan marker di `/data`. | Mencegah path traversal/live SQLite replacement dan mengikuti spec. |
| D-019 | DEK rotation dapat batch secara synchronous-resumable dengan explicit operation state; write target environment diblokir. | Meminimalkan lock untuk data besar tanpa worker dan tanpa state ciphertext ambigu. |
| D-020 | Service/environment names dibandingkan case-insensitive melalui normalized companion columns; variable key wajib pola portable `[A-Za-z_][A-Za-z0-9_]*` dan case-sensitive. | Menghindari nama UI duplikat; key tetap kompatibel luas dengan dotenv/shell dan tidak diam-diam dinormalisasi. |
| D-021 | DELETE item menyimpan proposed metadata dari current snapshot tetapi tidak proposed value. | Memungkinkan review jelas tanpa menyimpan ciphertext duplikat yang tidak perlu. |
| D-022 | Approver dan applier boleh user yang sama pada MVP. | Four-eyes control tidak diwajibkan; kedua aksi tetap terpisah dan diaudit agar dapat diperketat kelak. |
| D-023 | Request restore/rotation hanya serial per target melalui partial unique index operation aktif. | Menghindari dua maintenance operation menulis key/database state yang sama. |
| D-024 | Login pertama privileged bootstrap menghasilkan session `PASSWORD_ONLY` yang hanya boleh mengakses enrollment TOTP dan logout; konfirmasi TOTP merotasi session menjadi `FULL`. | Mendamaikan bootstrap yang hanya menyediakan email/password dengan kewajiban TOTP Operator/Administrator tanpa memberi akses aplikasi sebelum 2FA aktif. |
| D-025 | `CONFIGDECK_ENV` wajib eksplisit. Production hanya menerima KEK dari secret file; fallback environment KEK hanya untuk development/test. | Mencegah deployment release diam-diam berjalan dalam mode development atau menurunkan kontrol key/cookie. |
| D-026 | Serve pada database tanpa user wajib menerima kedua bootstrap credential; password bootstrap minimum 12 byte. Command migration tetap dapat berjalan tanpa credential/KEK. | Menghindari instance hidup tetapi tidak dapat diamankan/login, sekaligus mempertahankan deployment migration terpisah. Parameter password dapat diperketat sebelum production. |
| D-027 | Release profile memakai optimasi Cargo standar dengan symbol stripping; LTO/codegen-unit tuning ditunda sampai benchmark Phase 5. | Menjaga release build praktis pada mesin kecil. Ukuran/latency binary harus diputuskan berdasarkan benchmark, bukan asumsi. |
| D-028 | QR enrollment TOTP dibuat in-process sebagai SVG lalu di-embed sebagai data URI pada response `no-store`; setup key manual tetap tersedia. | Secret enrollment tidak dikirim ke CDN, API QR, atau service eksternal. SVG tidak memerlukan runtime image library atau JavaScript. |
| D-029 | `docker-compose.yml` tetap production/fail-closed. HTTP localhost memakai `docker-compose.local.yml` yang hanya mengubah `CONFIGDECK_ENV=development`. | Cookie `Secure` wajib di production, sedangkan smoke test HTTP localhost memerlukan cookie development non-Secure. Override tidak mengubah volume, port loopback, atau hardening container lainnya. |
| D-030 | Nama service/environment ditrim, wajib 1–100 karakter Unicode, dan deskripsi maksimal 1.000 karakter; normalized name adalah lowercase dari hasil trim. | Spec menentukan uniqueness case-insensitive tetapi tidak menentukan batas input. Guardrail ini mencegah input kosong/berlebihan sebelum menyentuh SQLite dan masih cukup longgar untuk metadata operasional. |
| D-031 | Archive service/environment bersifat reversible dan tidak menghapus row, DEK, variable, history, request, atau access grant. Environment baru ditolak pada service archived; variable mutation ditolak pada environment/service archived. | Menjaga referential integrity dan audit/history. Archive adalah lifecycle metadata, bukan deletion cascade. |
| D-032 | Preview import `.env` dibawa sebagai token AEAD berumur maksimal 30 menit yang terikat ke user, session, dan environment; HTML hanya membawa ciphertext token, bukan hidden plaintext. | Memungkinkan preview lalu pemilihan visibility/type tanpa menambah tabel draft atau memantulkan secret ke field tersembunyi. Token gagal bila diubah, dipakai session lain, kedaluwarsa, atau KEK berubah. |
| D-033 | Import dibatasi 256 KiB, 500 variable, key 255 byte, dan value 32 KiB. Parser menerima assignment data-only, optional `export`, full-line comment, serta quoted escape yang eksplisit; tidak melakukan interpolation, substitution, atau shell parsing. | Memberi batas resource yang konservatif dan perilaku deterministik. Duplicate key, syntax ambigu, NUL, escape tidak dikenal, serta key invalid ditolak sebelum token preview dibuat. |
| D-034 | Grant service pada MVP hanya dikelola Administrator untuk user Contributor aktif. Setiap grant/revoke menaikkan `auth_version` target dan mencabut seluruh session aktif target. | Operator/Administrator sudah memiliki scope global. Invalidasi session memastikan perubahan authorization segera berlaku dan tidak bergantung pada session lama. |
| D-035 | Satu change set dibatasi maksimal 50 item, title 200 karakter, dan reason 1.000 karakter. Key tidak boleh duplikat di dalam change set. | Menetapkan guardrail resource yang belum dirinci SPEC, menjaga review tetap operasional, dan mencegah urutan perubahan ambigu untuk key yang sama. |
| D-036 | Authenticated UI memakai app shell konsisten dengan dashboard ringkasan, sidebar berlabel, navigasi role-aware, dan account menu. Route backend yang sudah ada tetap dipertahankan; label berorientasi tujuan seperti `Configurations` dan `Changes`. | Mengurangi jargon dan memberi orientasi tanpa mengubah kontrak keamanan atau workflow backend menjelang Phase 3B. |
| D-037 | Recent authentication bukan menu utama. Tindakan sensitif mengarahkan ke halaman konfirmasi identitas dengan `return_to` internal yang divalidasi ketat, lalu kembali ke konteks awal; account menu hanya menampilkan status/shortcut. | Recent-auth adalah step-up security control, bukan area kerja. Validasi relative-path mencegah open redirect dan tidak menggantikan authorization backend. |
| D-038 | English tetap bahasa default selama Phase 3–4. EN/ID translation catalog dan selector diselesaikan pada Phase 5 setelah copy workflow stabil. | Menghindari pemeliharaan dua terjemahan saat halaman masih berubah, sambil menetapkan dukungan bilingual sebagai scope polish eksplisit. |
| D-039 | Light/dark theme dibangun bersama UI foundation memakai CSS design tokens. Default mengikuti sistem dan override manual disimpan sebagai preferensi non-sensitif di browser; tidak ada secret atau state authorization di browser storage. | Tema memengaruhi seluruh CSS sehingga lebih murah dibangun sekarang, sedangkan preference lokal tidak memperluas trust boundary keamanan. |
| D-040 | ConfigDeck bersifat deployment-platform agnostic. UI, dokumentasi, domain copy, test fixture, dan roadmap memakai istilah generik `deployment platform`; tidak ada asumsi vendor atau integrasi vendor pada MVP. | Produk harus dapat dipakai bersama platform deployment apa pun. Workflow tetap manual dan status `APPLIED` hanya menyatakan Operator telah mengonfirmasi perubahan pada platform tujuan, bukan bahwa ConfigDeck melakukan deployment. |
| D-041 | Resulting preview menyimpan SHA-256 fingerprint atas canonical snapshot request revision, item revision/base version, dan seluruh current variable version/lifecycle pada environment. Apply menghitung ulang snapshot di dalam transaction dan wajib cocok dengan fingerprint yang dilihat user. | Mengikat `Mark Applied` pada preview yang benar tanpa menyimpan plaintext. Perubahan current state, fulfillment, approval revision, atau item metadata membuat preview stale dan apply gagal aman. |
| D-042 | Batch preview/apply hanya menerima request `READY_TO_APPLY` dari satu environment dan menolak key yang dipengaruhi lebih dari satu selected request. Satu-request preview memakai jalur batch yang sama. | Mencegah urutan overlay ambigu dan menjaga apply seluruh selection atomik. Conflict harus diselesaikan sebagai request/rebase baru, bukan last-write-wins. |
| D-043 | Semua resulting preview dan `Mark Applied` mewajibkan recent authentication Standard untuk Operator/Administrator, walau selection hanya berisi public values. | Konfirmasi bahwa konfigurasi telah diterapkan pada platform tujuan adalah tindakan privileged; aturan seragam mengurangi edge case dan biasanya memakai window yang baru dibuat saat preview. |
| D-044 | Daftar variable menyediakan shortcut `Request change` per baris untuk update atau deletion yang menghasilkan one-item change set; multi-item request builder tetap tersedia untuk perubahan terkait. Direct already-deployed recording tetap terpisah dan hanya untuk Operator/Administrator. | Memberi alur cepat tanpa menyamarkan proposal sebagai edit current state dan tanpa menghilangkan kemampuan change set atomik multi-item. |
| D-045 | Shortcut update variable dibuka sebagai inline editor pada baris yang sama. Submit Contributor tetap membuat one-item change request; public value boleh diprefill, sedangkan restricted value selalu kosong bila backend tidak mengotorisasi plaintext. | Memberi pengalaman edit langsung tanpa mengubah authorization atau menyamarkan proposal sebagai mutasi current state. Type-aware control berubah mengikuti pilihan type dan backend tetap menjadi validator final. |
| D-046 | Import `.env` menyarankan `multiline`, `boolean`, `integer`, `url`, atau `string` secara konservatif dari value setelah parsing. Saran hanya menentukan default select pada preview, dapat dioverride, dan plaintext tidak ikut ke preview HTML. | Mengurangi input manual tanpa mengubah string asli, visibility default restricted, token preview AEAD, atau validasi commit. Nilai ambigu tetap `string`. |
| D-047 | First-run organization setup hanya tersedia setelah bootstrap Administrator berhasil login dan menyelesaikan TOTP. Startup tetap membuat initial Administrator dari environment, lalu authenticated wizard meminta organization name dan optional logo sebelum halaman aplikasi normal. | Mencegah unauthenticated first-user takeover sambil memungkinkan branding organisasi diinput melalui UI. Existing database ditandai sudah onboard saat migration; database baru tetap membutuhkan wizard. |
| D-048 | Logo ConfigDeck adalah trusted SVG lokal yang dibundel bersama aplikasi. Logo organisasi hanya menerima upload PNG/WebP maksimal 256 KiB, divalidasi MIME dan magic bytes, lalu disimpan di SQLite; remote image URL dan user-uploaded SVG tidak dirender pada MVP. | Menjaga aplikasi offline/lightweight dan menghindari script SVG, tracking eksternal, CSP exception, serta SSRF. File logo ikut backup database dan tidak bergantung pada CDN. |
| D-049 | Administrator dapat membuat account melalui `Users & Access` dengan role tetap dan initial password minimal 12 byte. Password langsung di-Argon2id dan tidak pernah disimpan/log sebagai plaintext; UI mengingatkan pengiriman melalui kanal aman. | Membuka pengujian Contributor dan administrasi dasar tanpa default account/credential. Forced first-login password change kemudian diselesaikan oleh D-057 pada Phase 4A. |
| D-050 | Identitas visual ConfigDeck memakai logo SVG lokal yang dibundel, tagline `Configuration Management Platform`, dan palet graphite-orange pada dark/light design tokens. Organization branding tampil terpisah dari product branding. | Memberi hierarki produk/workspace yang jelas, tetap ringan tanpa font/icon/CDN eksternal, dan mempertahankan preference tema non-sensitif yang sudah ada. |
| D-051 | Pembuatan service secara atomik juga membuat `Development`, `Staging`, dan `Production` beserta DEK aktif masing-masing. UI environment tidak lagi meminta pembuatan standar; custom environment tetap opsi lanjutan yang collapsed. | Menghilangkan setup berulang dan empty state yang membingungkan tanpa mengunci organisasi yang membutuhkan QA/preview/sandbox. Atomic transaction mencegah service dengan sebagian default environment. |
| D-052 | Import preview tetap fail-safe dengan default `restricted`, tetapi menyediakan pencarian key dan bulk visibility untuk hanya baris yang sedang terlihat. Tidak ada inferensi public/secret otomatis dari nama key. | Mempercepat review import besar tanpa membuat heuristic salah yang berpotensi mempublikasikan credential. User tetap mengambil keputusan eksplisit sebelum commit. |
| D-053 | Error route web dirender sebagai halaman HTML yang ramah dengan tindakan kembali/coba lagi; route `/api/*` tetap menghasilkan JSON terstruktur. Detail internal/database/crypto tidak pernah ditampilkan. | Browser tidak lagi memperlihatkan raw JSON sementara kontrak API dan sanitasi error tetap terjaga. |
| D-054 | Pada daftar variable, value menjadi trigger edit inline yang keyboard-accessible untuk role yang boleh membuat request. Tombol Copy per-row dihapus; reveal tetap terpisah dan tindakan deletion dipindahkan ke menu ringkas. | Mengurangi kepadatan action tanpa mengubah semantics: edit tetap membuat change request, restricted value tetap masked, dan mutation tetap ditegakkan backend. |
| D-055 | Kontrol tema memakai switch visual dua-keadaan dengan ikon matahari/bulan, label current theme, `aria-pressed`, dan preference lokal yang sama. | Membuat affordance pengaturan lebih jelas daripada link teks tanpa menambah state server atau dependency aset. |
| D-056 | Perubahan role, active state, dan reset TOTP memerlukan recent-auth Administrator, menaikkan `auth_version`, mencabut seluruh session target, dan diaudit. Administrator tidak boleh mengubah role/status dirinya sendiri atau mereset TOTP sendiri dari daftar user; Administrator aktif terakhir tidak dapat dinonaktifkan atau diturunkan. | Menghindari privilege escalation, session lama yang tetap memiliki hak, dan organisasi kehilangan seluruh Administrator. Recovery Administrator sendiri memerlukan Administrator kedua sesuai desain tanpa recovery code MVP. |
| D-057 | Account yang dibuat melalui UI dan bootstrap Administrator baru memiliki `must_change_password=1`. Setelah password dan TOTP yang diwajibkan tervalidasi, user hanya dapat membuka halaman ganti password sampai password awal diganti; aksi tersebut mencabut seluruh session dan meminta login ulang. Existing user saat migration tidak dipaksa berubah. | Memastikan initial password yang dibagikan bukan credential jangka panjang tanpa mengunci instalasi yang sedang di-upgrade. TOTP enrollment didahulukan agar password-change session sudah memiliki assurance role yang diwajibkan. |
| D-058 | Audit UI tersedia untuk Operator/Administrator, dibatasi 200 event terbaru, dapat difilter berdasarkan action/outcome/actor, dan hanya merender primitive metadata dari allowlist eksplisit. JSON mentah, ciphertext, body, dan unknown metadata tidak ditampilkan. | Memenuhi kebutuhan operasional sambil mencegah field baru yang tidak direview menjadi jalur kebocoran pada audit viewer. Pagination lanjutan dapat ditambahkan bila volume nyata memerlukannya. |
| D-059 | Recent-auth hanya dipicu secara just-in-time oleh tindakan sensitif. Account menu tidak menawarkan proactive privilege elevation. Untuk POST administrasi user, session yang belum recent diarahkan ke konfirmasi identitas lalu kembali ke daftar; user mengirim ulang aksi secara eksplisit dan pending POST tidak diputar otomatis. | Menjelaskan bahwa recent-auth bukan kenaikan role, mengurangi kebingungan Operator/Administrator, dan mencegah penyimpanan atau replay otomatis payload perubahan setelah autentikasi. Backend tetap memeriksa capability dan freshness saat commit. |
| D-060 | Halaman `Configurations` memakai pola resource catalog: compact create action, client-side search/sort atas service yang sudah diotorisasi dan dirender server, serta Grid/List toggle dengan preference non-sensitif `configdeck.serviceView` di localStorage. Tanpa JavaScript seluruh service tetap terlihat dalam grid default. Card hanya menampilkan metadata nyata—environment, Contributor aktif, updated time untuk sorting, dan archived state—tanpa UUID atau health indicator semu. | Mengadopsi affordance referensi tanpa menambah endpoint, dependency, trust boundary, atau klaim status operasional yang tidak dimiliki ConfigDeck. Data authorization tetap ditentukan backend; browser hanya menata subset yang sudah boleh diterima user. |
| D-061 | Istilah UI `Service` diganti menjadi `App` pada area Configurations, dashboard, environment, dan access copy. Model domain, database table, route `/services`, serta API tetap memakai `service`. Card App menjadi click target utama melalui stretched title link; aksi Administrator dipindahkan ke menu overflow dan tetap berupa control terpisah di atas overlay link. | `App` lebih mudah dipahami user tanpa migration/compatibility break. Pemisahan stretched navigation link dan control menu menjaga HTML valid, keyboard accessibility, serta mencegah form Archive/Edit ikut terpicu saat card dibuka. |
| D-062 | Aksi App Administrator tidak memakai menu tiga titik. Manage access, Edit, dan Archive/Restore tampil sebagai lightweight icon controls di header card; Edit dan Archive memakai focused popover agar form/destructive confirmation tidak memenuhi card. Asset CSS/JS/theme memakai `no-store` di development dan cache terbatas di production. | Screenshot menunjukkan HTML baru dapat tercampur asset lama karena cache satu jam, menghasilkan layout rusak dan copy lama. Icon controls lebih mudah ditemukan, sedangkan development no-store membuat iterasi visual deterministik tanpa melemahkan cache production. |
| D-063 | Phase 4B memakai server-configured `backup_dir` (default `/backup`) dan `restore_intent_path` (default `/data/restore-intent.json`). Browser hanya mengirim basename backup tervalidasi. Marker menambahkan SHA-256 dan ukuran snapshot ke metadata minimum SPEC; restore tetap offline dan tidak ada endpoint yang mengganti database live. | Checksum/size mengikat intent pada snapshot yang dipilih tanpa menyimpan secret. Path dari trusted process configuration mendukung disposable tests, sedangkan strict basename, regular-file, canonical-directory, dan symlink checks menjaga allowlist production. |
| D-064 | Shell desktop memakai sticky top bar untuk breadcrumb, icon-only theme control, dan account menu; sidebar dapat diciutkan dengan preferensi lokal `configdeck.sidebarCollapsed`. Breadcrumb SSR dipindahkan secara progressive enhancement dan tetap berada di konten tanpa JavaScript. | Kontrol akun tidak lagi terselip di bawah sidebar, ruang horizontal dapat dipulihkan, dan preferensi UI tetap browser-only tanpa data sensitif atau perubahan authorization. Hover tidak menjadi satu-satunya mekanisme interaksi. |
| D-065 | Seluruh environment card adalah target navigasi keyboard-accessible melalui stretched title link; tombol `Open configuration` dihilangkan dan kontrol edit tetap berada di atas link card. Halaman pemilih environment dipertahankan sampai workspace perbandingan Phase 5 siap menggantikannya. | Mengurangi aksi duplikat dan memperbaiki card yang sebelumnya hanya dapat dibuka melalui tombol. Mempertahankan halaman mencegah alur kosong sebelum pengganti lintas-environment lolos gate phase. |
| D-066 | Top bar tidak mengulang merek ConfigDeck, email, atau role yang sudah tersedia melalui konteks login/sidebar. Breadcrumb hanya menampilkan lokasi halaman, account trigger menjadi kontrol ikon ringkas, dan sidebar collapse memakai simbol dengan accessible label/tooltip tanpa teks visual. | Mengurangi redundansi visual sambil mempertahankan nama kontrol untuk keyboard dan assistive technology. |
| D-067 | Selama KEK baru berbeda dari registry aktif atau ada operasi rotasi nonterminal, seluruh mutasi aplikasi selain autentikasi/logout dan endpoint resume rotasi diblokir secara global. DEK rotation memakai batch 64 row yang menemukan pekerjaan tersisa melalui `dek_version` lama dan mencakup semua proposal terenkripsi, termasuk request terminal, sebelum material DEK lama dihapus. | Global write pause lebih konservatif daripada per-environment lock tetapi sederhana dan fail-closed untuk monolith MVP. Migrasi seluruh proposal memastikan tidak ada referensi ciphertext ke DEK lama setelah finalisasi dan membuat resume tidak membutuhkan cursor plaintext atau worker. |
| D-068 | D-066 dikoreksi untuk account control: email dan role tetap terlihat sekali pada trigger top-bar, sedangkan dropdown tidak mengulang identitas tersebut dan hanya berisi status recent-auth bila aktif serta Sign out. Collapse control ditempatkan menempel pada garis batas kanan sidebar; breadcrumb memakai satu tipografi konsisten pada seluruh level. | Trigger ikon saja menghilangkan konteks user yang sedang aktif. Koreksi ini mempertahankan pengurangan redundansi di dropdown tanpa mengorbankan identitas session yang penting pada aplikasi internal. |
| D-069 | Kegagalan batch DEK mempertahankan status resumable dan material key, serta menyimpan failure code tahap yang tidak sensitif (`CURRENT`, `HISTORY`, atau `PROPOSAL`) untuk diagnosis. UI dan log tidak menampilkan row ID, nama key, ciphertext, nonce, atau plaintext. | Smoke data nyata dapat memiliki fault yang tidak tercakup fixture kecil. Stage-level telemetry mempercepat diagnosis tanpa memperluas permukaan kebocoran dan tanpa menandai operasi gagal permanen sebelum recovery diputuskan. |
| D-070 | Direct registry apply mengenkripsi current/history dan proposed-value secara terpisah dengan typed AAD masing-masing, walaupun plaintext input-nya sama. DEK rotation menerima satu jalur compatibility yang sempit untuk record legacy berjudul persis `Direct registry apply`, berstatus `APPLIED`, bersumber `OPERATOR_PROVIDED`, dan memiliki relasi immutable version; ciphertext legacy dibuka dengan metadata current-version relasional lalu langsung dienkripsi ulang sebagai proposal canonical. | Implementasi lama menyalin blob current-value ke kolom proposal sehingga metadata menyatakan proposal tetapi AEAD-nya terikat pada AAD current. Jalur compatibility tidak mencoba candidate AAD bebas, tidak berlaku pada request user biasa, tidak mengekspos plaintext, dan menormalkan record saat rotasi berhasil. |
| D-071 | Entry App membuka workspace perbandingan lintas environment yang hanya mengambil metadata key terotorisasi: presence, open-change state, visibility, type, version, dan deployment status. Query tidak memilih ciphertext, nonce, atau plaintext; nilai tetap dibuka melalui halaman environment dan policy existing.
